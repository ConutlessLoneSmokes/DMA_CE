2026-10-20更新。角度继续固定为±60°，距离0.1–0.4 m；保持32阵元、32子载波和原8个观测条件。正式配置为 `configs/research.json`，短验证配置为 `configs/research_smoke.json`。

本版本修正SBL更新和停止判据，并强制执行不同基线预算进行独立检查。确定性精修只保留无可靠度版本，固定既有跨频3×3卷积和条件归一化损失；不再重跑结构、损失、完整方差图、标量及打乱对照。SBL推导见 [SBL_SOLVER.md](../SBL_SOLVER.md)。

## 运行方法

在服务器的 DMA_CE 仓库目录中，使用已配置好 CUDA 版 PyTorch 的 Python 环境运行：

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
python scripts/run_research.py --config configs/research_smoke.json --run-id server_smoke_20261020
python scripts/audit_research.py server_smoke_20261020
python scripts/run_research.py --config configs/research.json --run-id research_003 --stage baseline
```

先检查 `results/research_003/base_baseline/selection.json`：两种字典均应通过完整预算和稳定性检查。随后使用同一ID继续；`all` 会复用已完成的基线：

```bash
python scripts/run_research.py --config configs/research.json --run-id research_003
python scripts/audit_research.py research_003
```

同一命令可恢复已完成阶段和训练断点。每个阶段运行前检查所有前置阶段；配置、父运行或 `src/`、`scripts/` 中的执行源码有变化时必须使用新运行 ID。每个阶段的超时上限由 `timeout_seconds` 指定。失败保留状态、错误和最近的优化器、批次及扩散随机状态。

### 在修正后的运行上延长扩散训练

若新运行的扩散阶段在20,000步仍达到预算边界，可以继承它的三个扩散断点，在原CUDA环境中执行：

```bash
python scripts/run_research.py --continue-from research_003 --diffusion-checkpoints 30000 40000 --run-id research_004 --stage diffusion
python scripts/audit_research.py research_004 --validation-only
```

`--diffusion-checkpoints` 只列新增预算。程序从父运行读取配置，逐字节复制训练/验证缓存、模型和前五阶段结果到新 ID，保留原始20,000步优化器与两个随机数生成器的快照。恢复已有新 ID 时使用相同命令。父运行保持原样；新运行保存 `continuation.json`，审计核对继承文件哈希和旧日志前缀。复制中断且尚未生成该来源记录时，改用新的 ID。

原始20000步余弦日程和所有旧检查点保持不变；新增训练在其末端学习率继续。正式配置为 `0.001 × 0.1 = 0.0001`，不重新启动余弦衰减。确定性训练预算保持原值。最终新初始化的扩散模型也按同一原始日程加恒定末端学习率训练到验证选定步数。

`validation_audit.json` 中 `status=passed` 表示来源、断点和验证重放通过；`ready_for_final=true` 表示扩散阶段已通过当前稳定性规则。此时继续最终阶段：

```bash
python scripts/run_research.py --continue-from research_003 --diffusion-checkpoints 30000 40000 --run-id research_004 --stage final
python scripts/audit_research.py research_004
```

若最大检查点仍改善超过0.1 dB，程序记录 `budget_limited`、保存验证表格和执行报告并以状态码2停止。验证审计仍可核对已完成产物，完整审计会返回 `not_ready`。需要再次延长时，以尚未开始最终评价的 `research_004` 为父运行，使用更大的新增预算和新 ID。已创建最终冻结记录或筛选预测的运行不能作为续训父运行。

若服务器另有原第二轮的 `runs/deterministic_20261016_v1/data.pt` 和 `config_resolved.json`，可在第一次运行时附加 `--parent deterministic_20261016_v1`，之后每次恢复也保留这个参数。它只取训练和验证观测；物理系统、场景种子和样本数必须完全匹配。Git 不包含这些缓存，未提供父运行时程序会自行生成。

正式配置保留原有512训练、64验证、128筛选几何，以便使用相同物理观测重建粗估并比较。扩大数据量时修改 `data` 后使用新 ID。配置中的 `learning.steps` 保持兼容旧入口，新流程的实际训练预算来自 `research.checkpoints` 及阶段选择。

## 阶段与控制变量

| 计划 | 阶段 | 实际处理与输出 |
|---|---|---|
| 1. 基线与训练预算 | `baseline` | 同一验证观测比较49×7与97×13字典；强制完整执行1000/2000/4000/8000/16000次预算，逐字典检查一阶条件、完整CSI NMSE及后验方差稳定性 |
| 1. 基线与训练预算 | `curves` | 只训练无可靠度确定性精修，3个初始化；一条20000步轨迹保存2000/8000/20000步模型及训练/验证曲线 |
| 2. 固定已有结构 | `factorial` | 保存跨频卷积、条件归一化损失的固定选择，不新增对照训练 |
| 3. 单一确定性版本 | `reliability` | 保存无可靠度策略，不新增方差图、标量和置换训练；保留阶段名以保持记录和续训布局一致 |
| 4. 精度与计算量 | `budget` | 对100/300/500/1000次及稳定基线预算建立匹配精修器，重算训练标定，导出误差—SBL加精修时间图 |
| 4. 生成模型比较 | `diffusion` | 固定相同粗估、表示、结构和损失，比较训练检查点及1/4/16次输出平均；评价精度、调用数和总时间 |
| 5. 独立复核与通信 | `final` | 用5个新的初始化复核32×32，冻结模型后生成新筛选几何；评价匹配条件、同范围路径数失配及净速率 |

所有训练曲线采用相同的20000步余弦学习率日程；提前停止保留长训练的相同前缀。初始化种子和抽取批次的种子独立于几何种子。确定性和扩散模型使用相同的批次序列；扩散加噪使用另一个随机数生成器。训练时只把当前批次送到GPU，避免把128×128的整个训练缓存放入显存。

保留的网络使用跨频3×3卷积、宽度32、15,428个参数。无可靠度通道直接分配零占位，跳过后验方差的均值、标定、对数和标准化；CNN本身的运算量与原三种可靠度版本相同。条件损失权重等于全训练集平均粗估残差MSE除以该条件训练残差MSE，验证与筛选真值不参与标定。低层加载接口仍可读取历史版本模型。

## 选择、停止与新场景

稳定SBL基线要求相邻两个预算均执行全部更新，且两者总体一阶条件通过比例均≥95%、每条件均≥90%；每条件NMSE变化≤0.1 dB、平均方差相对变化≤5%。粗、密字典分别判断。缓存、逐场景表和汇总表保存实际更新数、一阶条件残差和目标值。未通过时保留表格，记录 `budget_limited` 并以状态码2停止；需要扩大预算时修改配置并使用新ID。

确定性训练预算按无可靠度版本3种初始化的验证集线性平均NMSE选择。SBL精修预算选择验证误差距最优精修≤0.1 dB的候选中，实测总均摊时间最短者；表格同时保留单独SBL，最终报告可据此判断精修是否有计算价值。

若最优训练检查点落在最大预算，且相比倒数第二检查点仍改善超过 `training_stability_db`，相应阶段保存 `budget_boundary.json` 并记录 `budget_limited`。正式配置阈值为0.1 dB。扩散训练可按上面的独立新 ID 续训入口延长；确定性训练的预算变化需要另建研究配置。最后区间始终指倒数第二检查点到末点，即使验证最优点位于更早位置也按此定义报告。短验证使用放宽阈值和极小迭代数，只检查执行逻辑。

最终5个训练初始化与选择阶段的3个初始化不重合。保留稳定粗/密字典SBL、预算匹配SBL、无可靠度确定性精修，以及同粗估和同表示的无可靠度扩散精修；扩散报告1/4/16次平均。观测一致性系数在确定性验证预测上选择，由全部方法共用，原输出和修正输出都记录。

每个系统的 `frozen_validation.json` 在读取筛选真值前保存模型哈希、训练缓存哈希、可靠度标定、方法和筛选种子。失配只改变真实信道生成；估计器继续使用训练系统的字典范围、噪声尺度和标定。原有筛选场景不进入新阶段选择。

正式配置的 `expansions` 当前为空，范围偏移也已移出 `mismatches`。短验证仍保留极小尺寸扩展和距离偏移，用于覆盖原有通用代码分支，数值只用于实现检查。将来扩展阵元时，可以按孔径平方比调整距离以保持相对瑞利距离，并对每个系统重新检查基线。

## 指标与输出

`runs/<id>/` 保存完整缓存、断点、预测、源码快照、来源清单和逐阶段状态。`results/<id>/` 保存配置、源码快照、逐场景表、选择结果、图和执行报告；不导出模型及原始训练缓存。

- 主误差先对线性NMSE取平均再转dB。逐条件表保留种子，避免把同一几何的多个条件当作独立重复。
- 每条指标记录同观测哈希、SBL版本、停止策略、一阶条件残差、实际迭代数、观测残差、行空间/零空间误差、修正能量和与真实残差的对齐。
- 最终配对区间同时重抽训练种子和几何场景；同一几何的条件、方法始终一起抽取。有限种子数量会限制区间稳定性。
- 时间为预热后的批量均摊时间，包含SBL及精修的数据传送和计算；字典、已知硬件矩阵及网络预热不计入在线时间。它不是单样本时延。对照应在同一服务器、相同批量大小下顺序运行。
- 训练曲线的训练侧NMSE用每条件固定前128个训练几何，验证侧使用完整验证集；优化损失日志来自实际训练批次。

通信评价对应当前单微带、单RF链模型。每个方法用其估计CSI，在本条件的J个可行DMA状态中选一个状态，整个数据块的全部子载波共用该状态；以真实信道计算该状态的平均 `log2(1+SNR)`。净速率乘以 `max(0, 1 - [J + switch_symbols×(J-1)]/coherence_symbols)`。默认相干块200个OFDM符号，单次切换开销0.1符号，两者都在配置中显式记录。完美CSI状态选择仅为评分上界。

`scripts/audit_research.py` 检查源码和模型哈希、训练集标定、几何划分、同观测、冻结时间，并从保存预测重算完整CSI误差、残差分解、通信速率、配对区间及固定模型重放。短验证通过只证明实现可执行与这些一致性检查通过，不构成论文主结果。

2026-10-20的39项检查通过，包含解析方差解、目标下降、重复列不变性、强制预算执行、旧SBL续训缓存拒绝及CPU/GPU训练续训一致性。完整短验证通过9组场景、4,032条指标重算和12次模型重放，差值均为零，见 [本轮实现验证](../IMPLEMENTATION_CHECKS.md)。这些记录用于实现核查，完整数据量下的方法收益由服务器新运行评估。
