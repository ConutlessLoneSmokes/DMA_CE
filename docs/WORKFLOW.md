# 研究与工程工作流程

本页说明这套 Matt Pocock skills 在 DMA_CE 中的使用时机。按任务需要选择，简单解释或小修正直接完成。

## 任务入口

| 当前问题 | 适用 skill | 完成依据 |
|---|---|---|
| 查原始文献、核实方法或工具能力 | `research` | 结论对应一手来源，区分原文事实与项目推断 |
| 异常结果、实现错误、运行退化 | `diagnosing-bugs` | 最小可复现证据，以及能区分候选原因的检查 |
| 已讨论清楚的工作需要长期跟踪 | `to-spec`；较大任务再用 `to-tickets` | issue 写清问题、范围、验收和证据位置 |
| issue 需要补信息或决定处理方式 | `triage` | 使用约定的五个状态标签 |
| 按明确规格实现 | `implement` / `tdd` | 新逻辑有针对性的数学、物理或回归检查 |
| 术语或架构边界有歧义 | `domain-modeling` / `codebase-design` | 定义与现有代码一致；必要的取舍留下理由 |
| 审查改动、准备交付 | `code-review` / `pr` | 按规格与仓库约定审查，报告实际验证与限制 |

任务跟踪操作见 [issue-tracker](agents/issue-tracker.md)，领域文档规则见 [domain](agents/domain.md)。修改工作规则时使用 `writing-for-agents`，保留简短入口，把分支细节放在相应文档。

## 实施与实验

1. 读取 [实验日志](EXPERIMENT_LOG.md) 和对应指南，确认现有结果、尚未执行的计划、调用位置与验收范围。保留已有未提交工作；范围需要隔离时使用 `codex/` 分支。
2. 先确定比较问题及控制变量。数据划分、公平信息、冻结顺序与负结果记录遵循根目录 [AGENTS.md](../AGENTS.md)；新配置的数值以 `configs/` 为准，解释原因写入指南。
3. 只修改实现目标所需的代码、调用方、配置和文档。新公式或非平凡逻辑先做相关检查；完整测试命令为 `python -m unittest discover -s tests -v`，是否跑完整套件取决于变更影响面。
4. 仿真先用独立 ID 验证小流程。耗时实验按已授权的范围和预算执行；记录配置、种子、环境、源码、冻结选择和逐场景结果。同一 ID 的恢复条件以对应入口为准。
5. 验收分别判断实现是否正确、结果是否可复算、科学解释是否被对照支持。交付更新对应 issue 与证据链接；需要提交或 PR 时围绕同一变更整理，既有无关工作保持独立。

## 文档归属

- README 提供项目与文档入口；[文档索引](README.md) 负责分类。
- 实验状态与简要结论更新 [EXPERIMENT_LOG.md](EXPERIMENT_LOG.md)；实现检查更新 [IMPLEMENTATION_CHECKS.md](IMPLEMENTATION_CHECKS.md)。
- 方法条件、推导与运行命令放在对应指南；逐场景数据、分析报告和审计随 `results/<id>/` 保存，完整模型与缓存保存在 `runs/<id>/`。
- 历史文献、旧计划和失败记录保留日期与证据；压缩重复摘要时保留通往原记录的链接。受哈希审计约束的结果与清单保持原内容。
- 新实验更新活动索引和该实验记录即可。正式同步或启动之前，核对目标机器上的工作树和运行身份。
